## 1. 제안 제목

# MAEK: Make AI-Enabled Knowledge

## AI 시대, 직원이 직접 업무 서비스를 만들 수 있도록 기업 지식과 데이터를 연결하는 플랫폼

MAEK은 기업 내부의 문서, 데이터, 시스템, 직원의 AI 활용을 하나의 구조로 연결해, 일반 직원도 안전하게 내부 업무 앱과 자동화 도구를 만들 수 있게 하는 플랫폼입니다.

핵심 메시지:

> AI 도입은 도구 구독에서 끝나지 않습니다.  
> 직원들이 AI로 업무 서비스를 만들기 시작하는 순간, 기업에는 지식 브레인, 데이터조회엔진, 안전한 엔드포인트, 바이브코딩 환경, 거버넌스가 필요해집니다.

MAEK은 바로 그 병목을 해결합니다.

## 2. 제안 배경

많은 기업이 AI를 도입하고 있습니다. 하지만 현장에서 가장 많이 나오는 질문은 여전히 단순합니다.

> 우리 회사는 AI를 어디서부터 어떻게 도입해야 하는가?

처음에는 챗봇을 써봅니다. 보고서 작성, 이메일 작성, 회의록 요약, 아이디어 정리 같은 개인 생산성 업무에 AI를 사용합니다. 일부 직원은 더 나아가 AI를 이용해 간단한 코드를 만들고, 자동화 도구를 만들고, 내부 업무를 개선할 수 있는 작은 앱을 만들어보기 시작합니다.

이 흐름은 이미 조직 안에서 조용히 시작되고 있습니다.

McKinsey의 2025년 조사에 따르면 응답자의 88%가 조직 내 최소 하나 이상의 업무 기능에서 AI를 정기적으로 사용한다고 답했습니다. 그러나 많은 조직은 아직 기업 전체로 AI를 확장하거나 실질적인 기업 단위 가치를 포착하는 초기 단계에 머물러 있습니다.

이제 기업의 과제는 단순히 AI를 도입하는 것이 아닙니다.

> 직원들이 AI로 만들어내는 새로운 업무 방식을 회사의 안전한 데이터, 지식, 시스템과 연결할 수 있는가?

이 질문에 답하기 위해 MAEK이 필요합니다.

## 3. 기업 안에서 실제로 벌어지는 변화

### 3.1 1단계: AI를 도입해야 한다는 압박이 생긴다

기업의 대표, 임원, 팀장들은 AI가 중요하다는 것을 알고 있습니다.

하지만 막상 내부에서는 다음과 같은 고민이 생깁니다.

```text
- AI를 어디에 써야 하는가?
- 직원들에게 어떤 도구를 제공해야 하는가?
- 보안 문제는 어떻게 관리해야 하는가?
- 실제 생산성 향상으로 이어지게 하려면 어떻게 해야 하는가?
- AI 도입이 단순한 유행으로 끝나지 않게 하려면 무엇이 필요한가?
```

처음에는 개인용 AI 구독, 문서 작성 보조, 회의록 요약, 검색 보조 정도로 시작합니다.

그러나 곧 일부 직원들은 더 적극적으로 AI를 사용하기 시작합니다.

### 3.2 2단계: 바이브코딩이 조직 안으로 들어온다

바이브코딩은 개발자가 아닌 사람도 AI와 대화하면서 앱, 자동화 도구, 웹페이지, 간단한 프로그램을 만들 수 있게 하는 흐름입니다.

Google Cloud는 vibe coding을 앱 구축을 더 접근 가능하게 만드는 소프트웨어 개발 방식으로 설명하며, 제한적인 프로그래밍 경험만 가진 사람도 애플리케이션을 만들 수 있게 된다고 설명합니다.

처음에는 조용히 시작됩니다.

```text
- 어떤 직원은 엑셀 자동화 도구를 만든다.
- 어떤 직원은 간단한 내부 웹페이지를 만든다.
- 어떤 직원은 반복 입력 업무를 줄이는 스크립트를 만든다.
- 어떤 직원은 팀 업무 요청을 관리하는 작은 앱을 만든다.
- 어떤 직원은 보고서 초안을 자동으로 만드는 도구를 만든다.
```

처음에는 실험입니다. 정식 프로젝트도 아니고, 전산팀의 공식 업무도 아닙니다.

하지만 결과물이 생각보다 괜찮습니다.

### 3.3 3단계: 직원들이 만든 결과물이 눈에 띄기 시작한다

팀장이나 리더가 보기 시작합니다.

```text
"이거 직접 만든 거야?"
"업무 시간이 줄었네?"
"다른 팀도 쓸 수 있겠는데?"
"이런 걸 더 만들어보면 좋지 않을까?"
```

작은 성공 사례가 생기면, 경영진이나 리더는 직원들에게 AI 활용을 독려하기 시작합니다.

```text
- AI 구독을 지원한다.
- 팀별로 AI 활용 사례를 공유한다.
- 직원들에게 생산성 도구를 만들어보라고 한다.
- 내부 업무를 자동화해보라고 권장한다.
- AI 교육이나 워크숍을 진행한다.
```

이 단계에서 기업은 중요한 전환점에 도달합니다.

> AI가 개인의 도구에서 조직의 업무 개선 도구로 이동하기 시작합니다.

Microsoft의 2026 Work Trend Index는 많은 경우 사람은 준비되어 있지만, 그 사람들을 둘러싼 조직 시스템이 준비되어 있지 않다고 설명합니다. 또한 AI impact는 개인 노력만이 아니라 문화, 관리자 지원, 인재 운영 같은 조직 요인의 영향을 크게 받는다고 분석합니다.

즉, 직원들은 이미 앞서가고 있습니다. 문제는 조직 시스템이 그 속도를 따라가지 못한다는 점입니다.

### 3.4 4단계: 작은 생산성 도구는 만들어지지만, 곧 한계가 드러난다

처음 바이브코딩으로 만들어지는 것은 비교적 단순합니다.

```text
- 간단한 웹페이지
- 내부 안내 페이지
- 엑셀 자동화 도구
- 윈도우용 작은 프로그램
- 업무 체크리스트
- 파일 정리 도구
- 보고서 초안 생성기
- 간단한 대시보드
```

이런 도구들은 분명히 효과가 있습니다. 직원은 스스로 업무를 개선할 수 있고, 팀 단위 생산성도 높아집니다.

하지만 곧 다음 단계에서 막힙니다.

```text
"회사 프로젝트 목록을 가져오고 싶다."
"ERP 데이터를 조회하고 싶다."
"인사 정보를 연동하고 싶다."
"고객사별 계약 정보를 보고 싶다."
"프로젝트별 리소스와 산출물을 연결하고 싶다."
"사내 문서와 실제 업무 데이터를 함께 조회하고 싶다."
```

여기서부터 문제가 생깁니다.

바이브코딩은 화면과 로직을 만들 수 있습니다. 하지만 업무에 필요한 데이터는 회사 내부 시스템 안에 있습니다.

```text
- ERP
- CRM
- 인사 시스템
- 프로젝트 관리 시스템
- 문서관리시스템
- 그룹웨어
- 엑셀
- 내부 DB
- 파일 서버
- 회의록
- 영상 자료
- 각 부서의 비공식 자료
```

직원이 만든 앱은 그 데이터에 접근할 안전한 방법이 없습니다.

### 3.5 5단계: 전산팀과 현업 사이에 새로운 갈등이 생긴다

현업은 말합니다.

```text
"앱은 만들 수 있는데 데이터가 필요합니다."
"프로젝트 목록만 조회할 수 있으면 됩니다."
"ERP 데이터 일부만 연결해주면 됩니다."
"고객 정보와 계약 문서를 같이 보고 싶습니다."
```

하지만 전산팀 입장에서는 부담이 큽니다.

```text
- 비개발자가 만든 코드를 어떻게 검토할 것인가?
- 그 앱을 누가 유지보수할 것인가?
- 보안 문제는 누가 책임질 것인가?
- DB 접근 권한을 어떻게 줄 것인가?
- 잘못 만든 앱이 내부 데이터를 노출하면 어떻게 할 것인가?
- 현업이 만든 앱을 정식 시스템으로 인정할 수 있는가?
```

그래서 현실적으로 이런 방식이 자주 발생합니다.

```text
- 필요한 데이터를 CSV로 내려준다.
- 엑셀 파일로 전달한다.
- 일회성으로 데이터를 복사해준다.
- 정식 API 연동은 뒤로 미룬다.
- 전산팀은 바이브코딩을 공식 지원하지 않는다.
```

이 방식은 단기적으로는 가능하지만, 곧 한계가 생깁니다.

```text
- 데이터가 최신 상태로 유지되지 않는다.
- 수작업 다운로드가 반복된다.
- 보안 통제가 약해진다.
- 직원별로 다른 파일을 사용한다.
- 앱이 많아질수록 관리가 불가능해진다.
- 조직 차원의 AI 활용으로 확장되지 않는다.
```

결국 병목은 코드가 아니라 데이터 연결과 운영 통제입니다.

### 3.6 6단계: 한편에서는 AI 시대를 위한 데이터 정비가 시작된다

기업 안에서는 또 다른 논의가 시작됩니다.

```text
"AI가 잘 활용하려면 데이터가 정리되어야 한다."
"문서를 AI가 읽기 좋은 형태로 바꿔야 한다."
"PPT나 워드보다 마크다운으로 정리하는 것이 좋지 않겠나?"
"기존 문서도 AI가 활용할 수 있도록 변환하자."
```

대표나 경영진이 이런 지시를 내릴 수 있습니다.

```text
"앞으로 주요 문서는 마크다운 형식으로 작성하자."
"기존 자료도 AI가 읽기 쉽게 마이그레이션하자."
"회의록, 매뉴얼, 프로젝트 자료를 정리하자."
```

그러면 회사 안에 새로운 자료가 쌓이기 시작합니다.

```text
- 마크다운 문서
- 변환된 회의록
- 프로젝트 요약 자료
- 매뉴얼 텍스트
- 교육 영상의 음성 변환 텍스트
- 고객사별 정리 문서
- 내부 정책 문서
- 업무 지식 문서
```

처음에는 좋아 보입니다. AI가 읽을 수 있는 데이터가 늘어나고, 기업 지식이 정리되는 것처럼 보입니다.

하지만 곧 또 다른 문제가 드러납니다.

### 3.7 7단계: 마크다운은 쌓였지만, 앱에서 사용할 수 없다

마크다운 문서가 많아졌다고 해서 곧바로 업무 서비스가 만들어지는 것은 아닙니다.

```text
마크다운이 있다
  != 프로젝트 목록 API가 있다

문서가 정리되어 있다
  != ERP 데이터와 연결되어 있다

AI가 읽을 수 있다
  != 앱이 안정적으로 조회할 수 있다

자료가 쌓여 있다
  != 권한과 보안이 적용된 업무 데이터가 있다
```

이 지점에서 기업은 중요한 병목을 만납니다.

> AI-ready 문서와 app-ready 데이터는 다릅니다.

직원이 바이브코딩으로 앱을 만들려면 단순한 문서 더미가 아니라, 다음이 필요합니다.

```text
- 검색 가능한 브레인 구조
- 업무 개념별 데이터 구조
- 프로젝트, 고객, 계약, 리소스 같은 엔티티
- 데이터 간 관계
- 조회 가능한 API 또는 엔드포인트
- 권한과 보안 정책
- 앱에서 사용할 수 있는 안정적인 데이터 인터페이스
```

마크다운은 좋은 시작점입니다. 하지만 마크다운만으로는 내부 앱이 만들어지지 않습니다.

### 3.8 8단계: 이제 필요한 것은 브레인 + 데이터조회엔진 + 바이브코딩이다

기업은 다음 단계로 넘어가야 합니다.

```text
1. 흩어진 문서와 데이터를 AI-ready 지식으로 만든다.
2. 그 지식을 브레인 구조로 연결한다.
3. 브레인에서 프로젝트, 고객, 리소스 같은 업무 개념을 추출한다.
4. 직원이 만든 앱이 사용할 수 있도록 조회 엔진과 API를 제공한다.
5. 바이브코딩 환경에서 그 데이터를 안전하게 사용하게 한다.
6. 전산팀은 보안, 권한, 감사, 운영을 통제한다.
```

이 전체 구조가 없으면 기업의 AI 활용은 다음 단계로 가지 못합니다.

```text
직원은 앱을 만들 수 있지만 데이터가 없다.
전산팀은 데이터를 알고 있지만 현업 앱을 지원하지 않는다.
경영진은 AI 확산을 원하지만 보안이 걱정된다.
문서는 정리되고 있지만 실제 업무 서비스와 연결되지 않는다.
```

MAEK은 바로 이 병목을 해결하는 솔루션입니다.

## 4. MAEK의 제안

## MAEK은 기업이 AI 도입 과정에서 겪는 병목을 해결하는 플랫폼입니다

MAEK은 단순한 챗봇이 아닙니다. 단순한 문서 변환 도구도 아닙니다. 단순한 바이브코딩 도구도 아닙니다.

MAEK은 기업 내부에서 자연스럽게 발생하는 다음 흐름을 하나의 체계로 연결합니다.

```text
AI 도입
  -> 직원들의 바이브코딩 실험
  -> 작은 업무 도구 생성
  -> 사내 데이터 필요
  -> 데이터 접근 병목
  -> AI-ready 데이터 정비
  -> 문서와 데이터의 브레인화
  -> 데이터조회엔진과 API 연결
  -> 바이브코딩 기반 내부 서비스 생성
  -> 보안과 운영 통제
```

MAEK의 역할은 이 전환을 기업이 안전하게 실행할 수 있도록 돕는 것입니다.

## 5. MAEK이 해결하는 핵심 문제

### 5.1 직원은 만들 수 있지만, 데이터가 없다

바이브코딩을 통해 직원은 화면과 기능을 만들 수 있습니다. 하지만 회사 데이터에 접근하지 못하면 실제 업무 서비스로 확장되지 않습니다.

MAEK은 직원이 필요한 데이터를 직접 DB에서 가져오게 하지 않습니다. 대신 기업의 자료와 데이터를 브레인 구조로 만들고, 승인된 방식으로 조회할 수 있게 합니다.

```text
기존:
직원이 데이터 요청
  -> CSV 다운로드
  -> 앱에 수동 반영

MAEK:
직원이 앱 생성
  -> 승인된 데이터조회엔진 호출
  -> 최신 데이터 활용
```

### 5.2 문서는 쌓였지만, 업무 데이터로 쓰기 어렵다

AI 시대를 위해 마크다운, 회의록, 문서, 영상 텍스트를 쌓는 것은 필요합니다.

하지만 그것만으로는 부족합니다.

MAEK은 단순히 문서를 저장하지 않습니다. 문서 안의 업무 개념과 관계를 추출하고, 조회 가능한 브레인 구조로 만듭니다.

예를 들어 기업 안에 다음 자료가 있다고 가정합니다.

```text
- 프로젝트 제안서
- 회의록
- 일정표
- 리소스 배정표
- 교육 영상
- 고객사 보고서
- 업무 매뉴얼
```

MAEK은 이 자료를 단순 검색 대상으로만 두지 않고 다음처럼 연결합니다.

```text
프로젝트
  - 관련 문서
  - 관련 회의록
  - 관련 영상
  - 담당자
  - 고객사
  - 일정
  - 산출물
  - 리소스
  - 주요 이슈
```

이렇게 되어야 직원이 만든 앱에서 다음 기능을 구현할 수 있습니다.

```text
- 프로젝트 목록 조회
- 프로젝트 상세 조회
- 프로젝트별 관련 문서 보기
- 프로젝트별 회의록 요약
- 프로젝트별 리소스 확인
- 고객사별 산출물 검색
```

### 5.3 전산팀은 통제하고 싶고, 현업은 빠르게 만들고 싶다

MAEK은 현업과 전산팀을 대립시키지 않습니다.

현업에는 빠른 생성 환경을 제공합니다.

```text
- 자연어로 앱 생성
- 업무 화면 생성
- 데이터 조회 기능 연결
- 검색 서비스 생성
- 자동화 도구 생성
```

전산팀에는 통제 가능한 구조를 제공합니다.

```text
- 승인된 데이터만 연결
- 사용자별 권한 적용
- 앱별 데이터 접근 범위 설정
- 로그와 감사 기록
- 배포 승인 절차
- 운영 중인 앱 관리
```

즉 MAEK은 다음 구조를 만듭니다.

> 현업은 빠르게 만들고, 전산팀은 안전하게 통제하고, 경영진은 조직 차원의 AI 확산을 관리합니다.

## 6. MAEK의 전체 구조

```text
[기업 내부 자료]
문서 / 마크다운 / 엑셀 / 영상 / 음성 / 이미지 / 시스템 데이터
        |
        v
[MAEK Brain]
AI가 이해할 수 있는 지식 브레인 생성
        |
        v
[MAEK Data Query Engine]
프로젝트, 고객, 계약, 리소스 등 업무 데이터 조회
        |
        v
[MAEK Endpoint Layer]
앱에서 사용할 수 있는 API / MCP / 커넥터 제공
        |
        v
[MAEK Vibe Coding Studio]
직원이 내부 업무 앱과 자동화 도구 생성
        |
        v
[MAEK Governance Center]
권한, 보안, 승인, 감사, 운영 관리
```

## 7. MAEK의 주요 모듈

### 7.1 MAEK Brain

## 흩어진 문서와 데이터를 기업 지식 브레인으로 전환

MAEK Brain은 기업 내부의 문서, 마크다운, 엑셀, 영상, 음성, 이미지, 업무 자료를 AI가 이해할 수 있는 구조로 변환합니다.

주요 기능:

```text
- 문서 분석
- 마크다운 데이터 정리
- 영상/음성 텍스트화
- 표와 구조 데이터 추출
- 업무 개념 추출
- 자료 간 관계 연결
- 검색 가능한 지식 인덱스 생성
- 근거 기반 응답 제공
```

MAEK Brain은 단순한 문서 저장소가 아니라, 기업 내부 자료를 업무에 활용할 수 있는 지식 구조로 만듭니다.

### 7.2 MAEK Data Query Engine

## 브레인에서 업무 데이터를 조회하는 엔진

MAEK Data Query Engine은 브레인 안에서 업무에 필요한 정보를 조회합니다.

예시:

```text
- 프로젝트 목록을 조회한다.
- 특정 조건의 프로젝트를 찾는다.
- 프로젝트별 관련 문서를 가져온다.
- 고객사별 계약과 회의록을 연결한다.
- 교육 영상에서 특정 주제를 검색한다.
- 부서별 업무 매뉴얼을 찾는다.
- 리소스 배정 현황을 조회한다.
```

중요한 점은 직원이 데이터베이스 구조를 몰라도 된다는 것입니다.

직원은 이렇게 요청합니다.

```text
"진행 중인 프로젝트 목록을 보여주는 화면을 만들어줘."
"프로젝트별 관련 문서와 회의록도 같이 볼 수 있게 해줘."
```

MAEK은 내부 브레인과 데이터조회엔진을 통해 필요한 정보를 찾고, 앱에서 사용할 수 있는 형태로 제공합니다.

### 7.3 MAEK Endpoint Layer

## 브레인을 앱에서 쓸 수 있는 연결 지점으로 전환

기업에서 가장 중요한 병목은 이 지점입니다.

```text
브레인은 있는데 앱에서 쓸 수 없다.
문서는 있는데 API가 없다.
마크다운은 있는데 데이터조회 기능이 없다.
```

MAEK Endpoint Layer는 이 문제를 해결합니다.

역할:

```text
- 브레인 안의 정보를 앱에서 조회 가능한 구조로 제공
- 필요한 경우 API 엔드포인트 생성
- MCP 기반 AI 도구 연결 지원
- 사내 DB 또는 ERP API와 연결
- 데이터 접근 권한 적용
- 앱별 데이터 사용 범위 통제
```

예를 들어 기존에는 `/projects` API가 없을 수 있습니다.

하지만 MAEK은 브레인에서 프로젝트 개념을 찾아내고, 앱에서 사용할 수 있는 조회 구조를 제공합니다.

```text
직원 요청:
"프로젝트 목록을 볼 수 있는 앱을 만들어줘."

MAEK 처리:
1. 브레인에서 프로젝트 관련 자료 탐색
2. 프로젝트 후보와 관계 추출
3. 프로젝트 목록 조회 구조 생성
4. 관련 문서, 회의록, 리소스 연결
5. 앱에서 사용할 수 있는 API 또는 조회 도구 제공
```

이것이 MAEK의 핵심 차별점입니다.

> MAEK은 문서를 쌓는 데서 끝나지 않고, 그 지식을 내부 앱이 사용할 수 있는 연결 지점으로 바꿉니다.

### 7.4 MAEK Vibe Coding Studio

## 직원이 내부 업무 서비스를 직접 생성

MAEK Vibe Coding Studio는 직원이 자연어로 필요한 내부 서비스를 만들 수 있게 합니다.

예시:

```text
"엑셀로 관리하던 업무 요청 목록을 웹앱으로 바꿔줘."

"프로젝트별 문서와 회의록을 볼 수 있는 화면을 만들어줘."

"고객사별 계약서, 제안서, 미팅 기록을 검색하는 서비스를 만들어줘."

"교육 영상에서 특정 주제만 검색할 수 있는 페이지를 만들어줘."

"부서별 업무 매뉴얼을 질문답변 형태로 조회하게 해줘."
```

직원은 개발자가 아니어도 자신의 업무에 필요한 도구를 만들 수 있습니다.

그러나 MAEK은 무제한 자유 개발 환경이 아닙니다. 기업에서 승인한 데이터, 권한, 정책 안에서 앱을 만들게 합니다.

### 7.5 MAEK Governance Center

## 보안, 권한, 승인, 감사 관리

바이브코딩이 기업 안으로 들어오면 보안 리스크도 함께 커집니다.

Axios는 2026년 5월 7일 보도에서 RedAccess 조사 내용을 인용해 Lovable, Base44, Replit, Netlify 등으로 만들어진 공개 접근 가능 자산 중 약 5,000개가 민감한 기업 데이터를 포함하고 있었다고 전했습니다. 다만 기사에는 관련 업체들의 반박과 "공개 앱 자체가 곧 보안 침해의 증거는 아니다"라는 입장도 함께 포함되어 있습니다.

따라서 기업용 바이브코딩에는 반드시 통제 구조가 필요합니다.

MAEK Governance Center는 다음을 관리합니다.

```text
- 누가 어떤 데이터를 사용할 수 있는가
- 어떤 앱이 어떤 데이터를 조회하는가
- 생성된 앱을 누가 승인하는가
- 민감정보는 어떻게 보호되는가
- 앱 사용 기록은 어떻게 남는가
- 운영 중인 앱은 누가 관리하는가
```

MAEK은 직원의 AI 활용을 막는 것이 아니라, 안전하게 확산시키는 것을 목표로 합니다.

## 8. MAEK이 만드는 새로운 기업 운영 방식

### 8.1 기존 방식

```text
현업이 아이디어를 낸다
        |
        v
전산팀에 개발을 요청한다
        |
        v
요구사항을 정리한다
        |
        v
일정을 기다린다
        |
        v
개발한다
        |
        v
배포한다
        |
        v
변경 요청이 다시 쌓인다
```

이 방식은 안정적이지만 느립니다. 작은 업무 도구와 빠른 실험에는 맞지 않습니다.

### 8.2 바이브코딩만 도입한 방식

```text
직원이 AI로 앱을 만든다
        |
        v
간단한 도구는 만들어진다
        |
        v
회사 데이터가 필요해진다
        |
        v
DB/API 접근에서 막힌다
        |
        v
CSV 파일을 받아 임시로 연결한다
        |
        v
보안과 유지보수 문제가 생긴다
```

이 방식은 빠르지만 위험합니다. 조직적으로 확장하기 어렵습니다.

### 8.3 MAEK 방식

```text
직원이 AI로 앱을 구상한다
        |
        v
MAEK Brain에서 회사 지식과 데이터를 찾는다
        |
        v
MAEK Data Query Engine이 필요한 정보를 조회한다
        |
        v
MAEK Endpoint Layer가 앱에서 쓸 수 있는 연결 지점을 제공한다
        |
        v
직원이 업무 앱을 생성한다
        |
        v
MAEK Governance가 권한과 보안을 통제한다
        |
        v
검증된 앱은 조직 자산으로 운영된다
```

MAEK 방식은 현업의 속도와 전산팀의 통제를 함께 만족시킵니다.

## 9. 대표 활용 시나리오

### 9.1 프로젝트 브레인 + 프로젝트 조회 앱

현재 문제:

```text
- 프로젝트 자료가 문서, 회의록, 엑셀, 영상에 흩어져 있음
- 프로젝트 목록은 최신 상태로 보기 어려움
- 관련 산출물과 리소스를 찾기 어려움
- 담당자가 바뀌면 맥락이 사라짐
```

MAEK 적용:

```text
1. 프로젝트 관련 문서와 회의록을 MAEK Brain에 등록
2. 프로젝트명, 담당자, 기간, 고객사, 산출물, 리소스 추출
3. 프로젝트 목록 조회 기능 생성
4. 프로젝트 상세 화면 자동 생성
5. 관련 문서, 영상, 회의록, 리소스 연결
```

결과:

```text
- 프로젝트 목록 조회 앱
- 프로젝트 상세 브레인
- 프로젝트별 관련 자료 검색
- 리소스 현황 조회
- 신규 담당자 온보딩 지원
```

### 9.2 고객사 지식 포털

현재 문제:

```text
- 고객사별 제안서, 계약서, 회의록이 흩어져 있음
- 과거 커뮤니케이션 이력을 찾기 어려움
- 영업 담당자가 바뀌면 고객 맥락이 사라짐
```

MAEK 적용:

```text
1. 고객사별 자료를 MAEK Brain으로 구성
2. 고객, 계약, 제안, 회의록, 담당자 관계 연결
3. 고객사별 지식 조회 화면 생성
4. 관련 문서와 요약 자동 제공
```

결과:

```text
- 고객사별 통합 조회 화면
- 계약/제안/회의록 연결
- 고객 대응 자료 자동 정리
- 영업과 PM 간 정보 공유 개선
```

### 9.3 인사/교육 자료 검색 서비스

현재 문제:

```text
- 사내 교육 영상과 매뉴얼이 많음
- 직원이 필요한 내용을 찾기 어려움
- 신규 입사자 온보딩이 담당자 의존적임
```

MAEK 적용:

```text
1. 교육 영상과 매뉴얼을 MAEK Brain에 등록
2. 영상 음성 내용을 텍스트화
3. 주제별 검색과 요약 기능 생성
4. 신규 직원용 온보딩 앱 생성
```

결과:

```text
- 교육 영상 검색
- 매뉴얼 AI 질의응답
- 신규 직원 온보딩 도구
- 반복 문의 감소
```

### 9.4 ERP/사내 데이터 조회 보조 앱

현재 문제:

```text
- ERP 데이터는 있지만 현업이 원하는 화면은 부족함
- 작은 조회 화면을 만들려 해도 전산팀 개발이 필요함
- 현업은 CSV 다운로드로 우회함
```

MAEK 적용:

```text
1. 승인된 ERP 조회 범위 정의
2. MAEK Endpoint Layer에서 조회 연결 구성
3. 현업이 필요한 조회 화면을 바이브코딩으로 생성
4. 권한과 로그를 MAEK Governance에서 관리
```

결과:

```text
- 부서별 맞춤 조회 화면
- CSV 수작업 감소
- 데이터 접근 이력 확보
- 전산팀의 반복 요청 감소
```

## 10. MAEK 도입 효과

### 10.1 직원 관점

```text
- 필요한 업무 도구를 직접 만들 수 있음
- 반복 업무를 줄일 수 있음
- 회사 자료와 데이터를 더 쉽게 찾을 수 있음
- 엑셀 중심 업무를 내부 앱으로 전환할 수 있음
- AI 활용이 실제 업무 개선으로 이어짐
```

### 10.2 전산팀 관점

```text
- 모든 소규모 앱을 직접 개발하지 않아도 됨
- 현업 앱의 데이터 접근을 통제할 수 있음
- 승인된 API와 데이터조회 구조를 제공할 수 있음
- 보안과 감사 로그를 확보할 수 있음
- 유지보수 불가능한 그림자 앱을 줄일 수 있음
```

### 10.3 경영진 관점

```text
- AI 도입이 실제 생산성 향상으로 연결됨
- 직원들의 AI 활용 사례를 조직 자산으로 만들 수 있음
- 데이터와 지식 정비 투자가 실제 업무 앱으로 이어짐
- 보안과 통제를 유지하면서 AI 확산 가능
- 부서별 성공 사례를 전사로 확산할 수 있음
```

## 11. MAEK 도입 로드맵

### Phase 1. 현재 상태 진단

```text
- 직원들의 AI 활용 현황 파악
- 바이브코딩으로 만들어진 내부 도구 조사
- 반복적으로 요청되는 데이터 식별
- CSV 다운로드로 처리 중인 업무 파악
- AI-ready 문서화 현황 확인
```

목표는 현재 회사 안에서 이미 시작된 흐름을 확인하는 것입니다.

### Phase 2. MAEK Brain 구축

```text
- 주요 문서, 마크다운, 회의록, 영상, 표를 등록
- 업무 개념과 관계를 추출
- 프로젝트, 고객, 계약, 리소스 등 핵심 엔티티 구성
- 검색과 요약 기능 검증
```

이 단계에서는 문서를 쌓는 것을 넘어, 업무에 활용 가능한 브레인 구조를 만듭니다.

### Phase 3. 데이터조회엔진 적용

```text
- 프로젝트 목록 조회
- 고객사별 자료 조회
- 계약/문서 관계 조회
- 교육 영상 검색
- 업무 매뉴얼 질의응답
```

이 단계에서 MAEK은 단순 검색 도구가 아니라, 내부 앱이 사용할 수 있는 데이터조회엔진으로 작동합니다.

### Phase 4. 바이브코딩 앱 생성

```text
- 프로젝트 조회 앱
- 고객 지식 포털
- 업무 요청 관리 앱
- 교육/매뉴얼 검색 앱
- 부서별 데이터 조회 대시보드
```

직원이 자연어로 필요한 업무 서비스를 만들고, MAEK이 브레인과 데이터조회엔진을 연결합니다.

### Phase 5. 보안과 운영 체계 확장

```text
- 사용자 권한 관리
- 앱별 데이터 접근 범위 설정
- 배포 승인 절차
- 감사 로그
- 민감정보 보호
- 앱 버전 관리
- 전산팀 운영 대시보드
```

이 단계에서 MAEK은 실험 도구가 아니라 기업의 내부 AI 업무 플랫폼으로 확장됩니다.

## 12. MAEK의 핵심 차별점

### 12.1 마크다운을 쌓는 것에서 끝나지 않는다

많은 기업이 AI 시대를 준비하기 위해 문서를 정리합니다. 하지만 문서 정리만으로는 업무 서비스가 만들어지지 않습니다.

MAEK은 문서를 브레인으로 만들고, 브레인을 데이터조회엔진과 앱 생성 환경으로 연결합니다.

```text
문서 정리
  -> 브레인화
  -> 데이터조회
  -> 엔드포인트 연결
  -> 업무 앱 생성
```

### 12.2 바이브코딩을 조직적으로 확장한다

일반적인 바이브코딩은 개인의 실험으로 끝날 수 있습니다.

MAEK은 이를 조직의 생산성 플랫폼으로 확장합니다.

```text
개인 실험
  -> 팀 도구
  -> 부서 서비스
  -> 전사 업무 자산
```

### 12.3 전산팀을 배제하지 않는다

MAEK은 현업이 마음대로 앱을 만들게 하는 도구가 아닙니다. 전산팀이 통제 가능한 구조 안에서 현업의 생산성을 높입니다.

```text
현업:
빠른 생성과 실험

전산팀:
데이터, 권한, 보안, 운영 통제

경영진:
AI 활용 성과와 확산 관리
```

### 12.4 단순 챗봇이 아니라 업무 서비스 생성 플랫폼이다

챗봇은 질문에 답합니다. MAEK은 지식을 기반으로 업무 서비스를 만듭니다.

```text
챗봇:
질문 -> 답변

MAEK:
질문 -> 지식 조회 -> 데이터 연결 -> 앱 생성 -> 운영
```

## 13. 대상별 제안 메시지

### 13.1 짧은 메시지

> MAEK은 기업 내부 지식과 데이터를 AI-ready 브레인으로 만들고, 직원들이 이를 기반으로 안전하게 내부 업무 서비스를 생성할 수 있게 하는 플랫폼입니다.

### 13.2 경영진 대상 메시지

AI 도입은 더 이상 도구 구독만으로 해결되지 않습니다.

직원들은 이미 AI로 업무를 바꾸기 시작했습니다.

이제 기업에는 그 흐름을 안전하게 확장할 수 있는 브레인, 데이터조회엔진, 바이브코딩 환경, 거버넌스가 필요합니다.

MAEK은 직원의 AI 활용을 조직의 생산성 자산으로 전환합니다.

### 13.3 전산팀 대상 메시지

MAEK은 현업이 만든 앱을 방치하는 도구가 아닙니다.

승인된 데이터, 권한, 로그, 배포 절차 안에서 현업이 필요한 업무 앱을 만들 수 있게 합니다.

전산팀은 모든 앱을 직접 개발하는 대신, 안전한 데이터와 운영 환경을 제공하는 역할로 전환할 수 있습니다.

### 13.4 현업 직원 대상 메시지

MAEK은 직원이 자신의 업무를 직접 개선할 수 있게 합니다.

회사 자료와 데이터를 활용해 필요한 화면, 검색 도구, 자동화 앱을 만들고, 반복 업무를 줄일 수 있습니다.

개발자가 아니어도 업무 아이디어를 실제 서비스로 바꿀 수 있습니다.

## 15. 결론

기업의 AI 도입은 다음 순서로 진행되고 있습니다.

```text
AI를 도입해야 한다
  -> 직원들이 개인적으로 AI를 사용한다
  -> 바이브코딩으로 작은 업무 도구를 만든다
  -> 결과물이 눈에 띄고 리더가 독려한다
  -> AI 구독과 활용 교육이 늘어난다
  -> 직원들은 더 많은 업무 앱을 만들고 싶어한다
  -> 회사 데이터와 지식에 접근해야 한다
  -> CSV, 수작업, 전산팀 병목이 발생한다
  -> AI-ready 문서와 마크다운 데이터 정비가 시작된다
  -> 하지만 문서만으로는 앱에서 사용할 수 없다
  -> 브레인 구조, 데이터조회엔진, 엔드포인트, 거버넌스가 필요해진다
```

MAEK은 바로 이 마지막 병목을 해결합니다.

> MAEK은 AI-ready 문서를 실제 업무 서비스로 연결하는 플랫폼입니다.

> MAEK은 바이브코딩을 개인 실험에서 조직의 생산성 시스템으로 확장합니다.

> MAEK은 직원의 창의성과 전산팀의 통제를 함께 만족시키는 기업용 AI 업무 플랫폼입니다.
